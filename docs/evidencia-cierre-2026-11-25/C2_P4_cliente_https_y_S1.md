# C2 · P4 · Referencia informativa USD/NIO

Rama de trabajo `feature/p1-base-seguridad-admin`, base `1b8de3a`, con los cambios acumulados de C1 y P2–P4 sin commit. La migración V15 se aplicó solo a bases de prueba desechables.

| Criterio | Evidencia |
| --- | --- |
| RF-M09-01 a RF-M09-03, integración y validación | **Verificado con S1 en Spring Boot.** `ExchangeRateApiClienteTest` comprueba GET para USD, cabeceras JSON y Bearer, tasa NIO de ocho decimales, coherencia temporal, banda 1–100, huella de respuesta, límite de tamaño y rechazo de redirecciones. **Inferido para el proveedor real.** La URL y el uso de Bearer coinciden con su [documentación de autenticación](https://www.exchangerate-api.com/docs/authentication). |
| RF-M09-04 y RF-M09-05, caché y H3 | **Verificado.** V15 crea el historial y una fila compartida para la concesión, programación y cuota. La instalación V0–V15 con `psql` sobre PostgreSQL 18 vacío, seguida de una segunda aplicación de V15, conserva una sola fila de control. `PostgresMigrationIT` abre el esquema con Hibernate en `validate` y verifica la fila inicial. `ExchangeRateApiClienteTest.h3ConservaCacheYComparteConcesionCalendarioYCuota` usa dos instancias de H3 con un S1 común, reloj controlado y H2. Verifica concesión, reintento de 60 segundos, `Retry-After`, cuarentena con valor y huella, suspensión de credenciales, conservación de caché y cupo de 100 intentos por mes. |
| RF-M09-06, procedencia y antigüedad | **Verificado por HTTP y JavaFX.** `ApiTasasTest` comprueba autenticación, ausencia de datos y atributos de una referencia histórica en `GET /api/v1/tasas/referencia`. En Windows se abrió la vista real como Asistente con el backend local y PostgreSQL desechable. La vista mostró la referencia histórica de 36.62430000 NIO por USD, la fuente, fecha y antigüedad. Tras añadir una referencia sintética de 36.73500000, el botón **Actualizar** mostró ese valor como informativo, con la fecha y antigüedad nuevas. |
| RF-M09-07 a RF-M09-09, autorización y pagos | **Verificado en H2 y PostgreSQL.** `ApiPagosTest.convierteConTasaAutorizadaYFallaSinTasa` comprueba que tener una referencia comercial para la fecha no habilita el pago entre monedas. El pago anterior conserva la tasa autorizada de 36.62430000 y la fuente BCN. `ApiTasasTest` comprueba el rol Propietario para autorizar y que la caché comercial se consulta aparte. |

La verificación `./mvnw.cmd -o -B verify -Ppostgres` terminó con **285 pruebas de la suite normal y 40 del perfil PostgreSQL**, con cero fallos, errores y omisiones. El recorrido visual encontró un error de carga FXML en el ancho mínimo del botón Reporte. Después de corregirlo, pasaron `FxmlControladoresTest`, `EstilosCssTest`, `ContrasteTest` y el recorrido visual descrito.

**No probado.** Para comprobar la conexión al proveedor real, ejecutar H3 con `LATCH_FX_API_KEY` desde el entorno del equipo consultor de prueba, esperar el intento programado y observar la referencia y su origen en la API local. Falta comprobar la variante LAN entre equipos físicos con PostgreSQL compartido y completar la revisión humana G6. El simulador cubre el contrato sin consumir cuota externa.

Invalidaría el resultado una llamada adicional mientras hay una concesión vigente, un fallo que reemplace la caché válida, una referencia comercial que se aplique a un pago o una discrepancia entre la referencia guardada y la que muestra JavaFX al actualizar.
